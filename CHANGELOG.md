## 3.11 (25 November 2026)

Shipped in `fm_name_editor.py`. Release 3.11 is a bug-fix release: Review changes, the Backups window and Undo now keep every promise they make on screen, and the test suite runs clean on Linux. Session 25 closes 3.11.

Session 25 — Review changes, the Backups window and Undo keep their word, and the suite runs clean on Linux:

- **An unticked file stays out of Deploy.** A file whose changes are all unticked is not written at all, wherever it would go. Before, Deploy could still replace the game's copy with the working copy's file as it is on disk when the two differed, or create a missing one, although Review changes said "not written"; the open file then pointed at the game's copy. That happened to a restored backup with its one tick cleared, and to a file with every change unticked. A file with no changes at all is still copied by Deploy, as before.
- **Restore selected names compares the names themselves.** Each comparison row keeps the open file's and the backup's names as lists, the tick box carries the row as it was compared, and the check before a restore compares those lists. A name may contain " | ", so two different sets of duplicate names could read the same in the table, pass the check, and restore names that were never shown. When one command, ID and language has more than one line, each name is now shown in quotes.
- **Undo and Redo take a selected restore's file state with them.** Undo clears the pending restore, where it came from and its whole-file tick, so earlier edits in that file can be ticked one by one again; Redo brings all three back; an earlier pending restore comes back exactly. A file that an Undo or Redo leaves with nothing pending is no longer flagged as a restore, so Save, Undo, Redo no longer marks the saved file as a pending restore. Undo is still one step.
- **"Restored …" stays.** After either kind of restore, the Backups window's summary keeps the restore message ahead of the fresh comparison, which used to replace it a moment later. Choosing another copy shows only that copy's comparison.
- **Clean on Linux.** Two older `Session19Engine` tests used Windows paths. They now check the same rules with each system's own paths; the letter-case check runs on Windows only.
- **Verification.** New `Session25Review` (4), `Session25Engine` (8) and `Session25Window` (4); each failed before its fix. Tests: 411 in the full suite, up from 395, run offscreen on Linux: all passed, with 5 that need the game's own name files skipped.

## 3.10 (25 November 2026)

Shipped in `fm_name_editor.py`. Release 3.10 makes Restore selected names in the Backups window read the backup in the background, like everything else that reads a backup, and check the restore properly against what was shown. Session 24 closes 3.10.

Session 24 — Restore selected names reads the backup in the background and refuses stale rows:

- **In the background.** Restore selected names reads the backup once and compares it again on the worker, while the Backups window waits: the lists, both restore buttons and Close are off until the answer comes. Closing the window part-way restores nothing. A backup that cannot be read is named, nothing is restored, and the buttons come back.
- **Stale rows are refused.** A ticked row is restored only when the fresh comparison still shows it with the same open name and the same backup name. A name changed in the open file after the list was shown, to any value, or a backup changed on disk, refuses the whole restore, and the list is compared again. Before, a name changed to a third value was overwritten without a word.
- **Names from the fresh read.** The restored names come from the read just made, not from the table's text, and each line is found through one lookup instead of a pass over every line for each tick. A person rule is matched by its ending too, so another rule with the same number and language is left alone. Undo still takes the whole restore back in one step, and nothing is written until Save or Deploy.
- **No tick box where a name alone cannot restore the row.** A row only in one file, or with a different number of lines in each, needs a line added or taken out, which only Restore into open file does; its tooltip says so. Before, ticking one restored nothing, or put every backup name into one line, and still reported it as restored.
- **Agent guides and private files.** The guides name Eve as release manager, and four private working files on this PC are ignored by git.
- **Verification.** New `Session24Engine` (6) and `Session24Window` (5); `Session18BackupRestore`, `Session23Window` and `Session8Workers` pass unchanged. ## 3.9 (24 November 2026)

Session 23 — Save timing, a responsive pack import and Backups window, and why the bytes differ:

- **Save timing.** Each part of a Save was timed on copies of a large data set across several runs. One part was clearly the cause: the reload after the write split every name in both files into words again for the right-click token index, although a Save changes no name. Closing the window part-way, or choosing another copy, drops the answer still on its way: nothing is shown or restored, and no error appears. While a copy is read for a restore, the lists and buttons wait.
- **Why the bytes differ.** When every supported name matches a backup but the files are not byte-identical, the Backups window lists why, read only: the encoding or BOM, line endings, comments, blank lines, unsupported lines, and name lines written differently, with counts and the first 20 lines. Files longer than 200,000 lines are not compared line by line.

## 3.7 (24 November 2026)

Shipped in `fm_name_editor.py`. Release 3.7 adds a short name and 3-letter code suggested from a club's long name, Name health checks with Fix formatting, and in-memory snapshots to roll back a run of changes. Session 21 closes 3.7.

Session 21 — short names and codes from the long name, name health, and snapshots (Release 3.7, note 09 proposals 3 to 5):

- **A short name and code suggested from the long name.** For a club with no short name or no 3-letter code, the inspector shows a suggestion first, for example short name "Man Utd" and 3-letter code "MUN" for Manchester United. Club-type words such as FC, AFC, SV or Club go from either end. A name still past the short-name guide of 14 then loses its numbers, shortens a few long words (United to Utd, Manchester to Man, Mönchengladbach to M'gladbach, and any spelling pairs you pinned), keeps the words before a joining word such as "de" (or the place after a describing word such as Olympique), and drops words from the end; a single long word is never cut. The code is three capital letters A to Z, from the initials of three words or more or else the first letters, and avoids the codes of the other clubs in the same file section where it can. Use suggestion, or Edit > Fill short name and code (Ctrl+Alt+D, also in the command palette), adds only the empty fields, just after the club's lines and in field order, as one Undo step; the inspector marks them Added (Suggested). A field that has a line is never changed. Clubs only.
- **Name health.** The status bar counts the open names with something to check, for example "Name health: 4 to check", or "Name health: clean": a space at an end or two in a row, a non-breaking or zero-width space, typographic punctuation (curly quotes, a backtick or an accent used as an apostrophe, an em dash; an en dash is left alone), a 3-letter code with lower-case letters, and a 3-letter code that another club (or nation) uses in the same file section. The file section stands in for a division, which the files do not record. Clicking the count lists them with a new Name health filter beside the search box; their Status reads Check, in amber, with the findings in its tooltip, and the inspector names each one. Checks only: nothing changes on its own.
- **Fix formatting.** Edit > Fix formatting, and the button in the inspector's Name health notice, tidy the names of the rows selected on the Entities tab as one Undo step: non-breaking spaces become plain ones and zero-width ones go, curly quotes and accent apostrophes become ', curly double quotes become ' too (a straight double quote cannot sit inside a name), an em dash becomes -, spaces in a row become one, the ends are trimmed, and 3-letter codes go into capitals. Only the quoted name of a line changes. A shared code is not a formatting fault, so it is left for you to decide.
- **Snapshots, in memory only.** Edit > Create snapshot… (Ctrl+Alt+K) keeps the open files' lines under a name you give. Edit > Roll back to snapshot lists them, newest first, with the time taken, and puts every open file's lines back as they were then, as one Undo step that Undo takes away again. Snapshots are never written to disk, go when files are opened again, and are kept to ten: taking another lets the oldest go and names it. A roll back after a Save or Deploy matches the lines to the file on disk again, so what differs from the file is a pending change, reviewed and ticked as usual.
- **Speed.** On copies of a large data set, a name-health pass takes about 42 ms, a snapshot about 75 ms, and rolling back a 500-name change about 120 ms. Adding lines, by Fill short name and code or a roll back that adds or takes out lines, reloads the views as typing into an empty field already does: about 0.6 s.

## 2.2 (11 November 2026)

Shipped in `fm_name_editor.py` and `FM Name Editor.bat`. A correctness and write-safety release built from the review of 2.1 (findings F1–F6). It adds no new features beyond what those repairs need; the window looks the same apart from a few labels and the Backups window.

Session 1 — correctness and write safety, part one (review findings F1, F2, F3):

- **One game-write preflight.** Save, Deploy, and the licensing toggle call the same check before touching the game tree. Save into the game folder was unguarded before; now it is refused while Football Manager is running, with the same message Deploy gives, and it asks for confirmation naming the exact files. When the process list cannot be read, the dialog says so and defaults to No instead of treating the game as closed.
- **Every field of a new line is checked.** Command, database id (ASCII digits), name, and language are validated before a line is formed, at pack import, older-file import, and entity-field insertion. A quote, a line break, or a control character in a language field is rejected and counted as a skipped row instead of becoming a second record in the file.
- **End-of-file insertion.** Filling an empty entity field beside a last line that has no line ending now gives that line its ending first, so the two commands no longer run together. Covered for LF, CRLF, and UTF-16 files.
- Tests: 33, up from 26. New cover for the preflight states, process-list failures, field checks, pack and older-file rejection, end-of-file insertion, and a window test of the refused Save.

Session 2 — correctness and write safety, part two (review findings F4 and F5, plus load and label items):

- **Unsaved means the bytes differ.** Each open file remembers the bytes it was read as, or last written as. It counts as unsaved whenever the lines in memory would write different bytes. Before, an edit followed by a revert could clear the flag while memory still differed from the file, so closing could skip the save prompt.
- **A restore stays pending until it is written.** Restoring a backup keeps the file on disk as the baseline. Restored rows that differ from the disk file show as Edited, rows the disk file does not have show as Added, and disk rows the backup lacks are counted as unsaved. Edited-only export after a restore lists exactly the rows that differ from disk. Reverting a restored row puts back the text on disk. Restoring a copy that matches the disk file leaves nothing unsaved.
- **Revert restores Greek person rules in full.** Both the matched ending and the replacement come back, and the status line counts person rules separately. The All lines view no longer overwrites its revert message straight away.
- **Opening files is all or nothing.** Every file is read first. If one cannot be read or decoded, a message names it and the files already open stay open. Before, a bad encoding could escape the error handler and a failed open emptied the workspace. The import dialog now catches decoding errors too.
- **Plainer labels.** "Missing short name" and "Missing code" are now "No short-name override" and "No code override". "Section" is now "File section", with a hint that it is the comment heading in the file and not a reliable country. The unsaved count includes restored and removed rows, and says "file differs from disk" when only comments or layout differ.
- Tests: 50, up from 33. New cover for restore baselines and pending state, repeated and failed restores, Greek rule revert in every order, all-or-nothing opening, the close prompt after a restore, and the new labels.

Session 3 — correctness and write safety, part three (review finding F6, backup identity, and the backup comparison):

- **Each file is replaced in one step.** Every write goes to a temporary file beside its destination, is flushed to disk, and is swapped in with a single `os.replace`. A failure leaves that file as it was, and the temporary file is removed. Save, Deploy, backup copies, the `.bak` beside an outside file, and pack export all take this route.
- **A file changed on disk is not overwritten.** Before anything is replaced, each file is read again and compared with the bytes the editor read when it opened the file, or last wrote it. If another program changed or removed it, nothing is written, and the message names the file and explains how to carry your edits across. A Deploy over a file that is not the one you opened has nothing to compare with; it is backed up and replaced, as before.
- **A failed write puts the earlier files back.** Save and Deploy replace files one at a time, not as one batch. If a later file cannot be replaced (for example, because another program holds it open), the files already replaced are put back from the copy taken before the write, a newly created file is removed again, and the message lists every file and where it stands. If a file cannot be put back, the message says so and names the backup copy that holds its previous version.
- **Backups describe themselves.** Each backup folder now holds a `manifest.json` recording the operation, the time, the database folder, the editor version, how the operation ended, and for each file its original path, size, SHA-256, encoding, BOM, date, and what happened to it. Two files with the same name get separate copies, and every copy keeps its original's date.
- **The Backups window matches by path.** A backed-up file is compared with, and restored into, the open file it came from, even when another open file has the same name. Backups made before 2.2 have no manifest and are matched by name, as before, and the window says so. Each backup in the list shows its operation, its file count, and any ending other than complete. `manifest.json` itself is not listed.
- **An honest comparison.** The Backups window reports differences in supported names and, separately, whether the files are byte-identical. A changed comment, blank line, or line ending no longer reads as a match.
- **Licensing toggle.** Its backup copy takes the same route and gets a manifest. The rename is one step inside one folder and never replaces a file: when both a name-mask file and its `.disabled` copy exist, the toggle refuses and the inspector shows "Present, and a .disabled copy too".
- Tests: 64, up from 50. New cover for a single-file write that fails, a failed first or second replacement, removal of a newly created file, a file that cannot be put back, files changed or removed on disk, two open files with one destination, manifests for UTF-8 and UTF-16 files, same-name copies, matching by path, the two-part comparison, the licensing rename, and window tests for a failed Deploy, a refused Save, and the Backups window.
